Root cause (both tests, one mechanism, not the library, not D38):
- **SwiftUI 18.x shares a drag between the sheet's own pan and a `.simultaneousGesture` drag recognizer.** On 17.5, 26.0, 26.5 and 27.0 any recognized SwiftUI drag takes the touch from the sheet (SHEET-s1). Controls with no ZTron code (`-ZTronSheetPlain`, 250 pt drag down at medium): `.simultaneousGesture(DragGesture)`, distance 0, `SpatialEventGesture` → sheet **dismissed** on 18.x (the gesture still sees 56–61 changes); `.gesture`, `.highPriorityGesture` → frozen. The library attaches its observer and pan with `.simultaneousGesture` (M3 §8), so on 18.x the sheet takes the drag *with* the view.
- **`testD1_ours`**: at large with the content scrolled to row 15 a 700 pt drag down **dismisses the sheet** and scrolls nothing (offset 660 stays; B1: sheet +140 pt, content unchanged; native scrolls to the top first). The next step of the harness tapped `sheet.reset` in a sheet that was gone. The finger moves with the sheet, so the pan's local translation stays ~0 (inferred).
- **`testSheetMediumScrollDisabledStopsTheView`**: the view *is* disabled: `envInside` 0 (`\.isScrollEnabled` reaches the reader through the sheet on 18.x), `dragBegan` 0 / `dragEnded` 0 (the pan never begins, D38 holds). What moved the offset is the viewport: on 18.x the sheet content is laid out at the **large** size first and at the detent size right after (pane 402 x 768 → 402 x 430; a native `ScrollView` shows the same trail), the first layout has no S7 centre rule and the second is a resize, so a never-touched view opens a medium sheet at offset (768 − 430) / 2 = **169** (`ot=169`, one `didScroll`, `vp` 376); the shared drag then resizes the sheet and S7 takes the offset 169 → 0 → 169 frame by frame (`vp` 376 ↔ 714). `reset()` had captured the 169 as `offMax`. A native `ScrollView` in the same sheet keeps `nativeOff` 0 (UIScrollView does not follow its bounds) and its sheet takes the drag too.
- 26.0 / 26.5 / 27.0 lay the content out at the detent size (402 x 436) from the start; 17.5 shows a degenerate 28 x 68 pane and then the detent size (393 x 419). Neither follows the 18.x pattern.
