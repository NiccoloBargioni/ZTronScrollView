Decisions (M8-1-n; not added to the D-list on purpose):
1. **Resolution order measured, not read from the design**: a hosted native `ScrollView` on 17.5 and 27.0 treats `showsIndicators: false` as the view's own default — an explicit `.visible` (on the view, on a parent) beats it, `.automatic` defers to it, `.hidden` / `.never` hide, per axis. Ours: per axis `member ?? twin ?? native env (16.4+) ?? .automatic`, and only an `.automatic` result becomes `.hidden` under `showsIndicators: false`. This matches the task text and contradicts §2/§10 of the design (corrected in its M8-1 addendum). `NativeIndicatorFixtureTests` holds the library against the hosted native view for 10 combinations.
2. **Config layering**: an optional per layer (an explicit `.automatic` overrides an outer `.hidden`); `AxisPair` instead of the design's tuple (tuples are not `Equatable`); `flashOnAppear: Bool?`; the trigger is `AnyEquatable` (the API is `Equatable`, not `Hashable`); member and twin triggers flash independently. `ZTronScrollView.chrome` is a separate property, not a field of M6's `ScrollViewConfig` (design: nothing of M5/M6 is touched).
3. **Native availability, confirmed against the iOS 27 SDK interface**: `scrollIndicators(_:axes:)` and the two env keys 16.0, `ScrollIndicatorVisibility: Equatable` 16.4 (so the env is read and `init?(_ native:)` exists from 16.4), `scrollIndicatorsFlash` 17.0. Below 16.4 the native env is not read (`nil`); no new `ZTronCapability` (a real `#available`, the structure never flips).
4. **Overlay position**: inside the viewport root, before `.ignoresSafeArea`. Measured by `theOverlayIsLaidOutAtTheViewportSize` (DEBUG probe): after `.ignoresSafeArea` the frame is the safe-area-respecting one (`ViewportObserver` adds the ignored insets back), inside it the overlay IS the viewport, also with `.automatic` / `.always` adjustment. The named space `ztronScroll.viewport` is NOT visible from the overlay (it is declared on the sibling subtree): chrome leaves take the viewport from `ScrollMetrics`.
5. **Activity** = `.interacting` / `.decelerating` / `.animating` with no resize open; `.tracking` (finger down, content not moving) shows nothing (UIKit shows the thumb when the content moves; the design said `phase ≠ .idle`). `.animating` is also the resize watch's phase, hence the resize exclusion.
6. **Fade without a frame clock**: `IndicatorController.isShown` flips on at once (no animation) and off through one `withAnimation(.linear(duration: 0.3))`; hold = `hideDelay` 0.4 after activity or `flashHold` 0.6 after a flash, one one-shot timer per deadline (`schedule` / `now` injectable; the state's clock). A flash under `.hidden` / `.never`, or before the view appears, is a no-op (no timer, not counted). `.visible` axes ignore the controller (opacity 1).
7. **`scrollIndicatorInsets` is `ScrollMetrics.indicatorInsets`** (cold, metrics channel): the leaf follows a change live with no new plumbing. Track inset = `adjustedContentInset − contentInset − refreshHold` (the safe area the content actually adjusts for: `.never` leaves the track alone, a refresh hold never moves it) + `scrollIndicatorInsets` + the view's `ChromeConfig.indicatorInsets` (M8-2's `contentMargins(for: .scrollIndicators)` writes it). One inset for both axes.
8. **`ChromeLeaf` reads undeclared channels as untracked snapshots** (a sample is always one consistent read; `overshoot` needs offset + zoom + metrics). A leaf with no channels never wakes: the indicator leaf is `[]` when no axis draws (`.hidden` / `.never` / `showsIndicators: false`), so a view without thumbs costs nothing per frame.
9. Thumb geometry is the design's formulas verbatim (`IndicatorMath.thumb`), plus: the track never goes below 0 (nil), `ℓ ≤ T` even when the minimum length exceeds the track, rubber-band `ℓ′ ≤ ℓ`, an axis outside `axes` draws only while zoom is enabled and the zoomed content exceeds the viewport on it (D15), `otherVisible` follows scrollability + visibility (not the fade), so the geometry does not jump while one thumb fades.
10. DEBUG probes (compiled out in release): `IndicatorController.lastRender` / `lastOverlaySize`, counters `chromeLeaf.body`, `indicators.host.body`, `indicators.flash`, `indicators.fadeOut`.
