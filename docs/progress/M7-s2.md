Decisions:
1. `scrollToTop(animated:)` did not exist and `shouldScrollToTop` / `didScrollToTop` had NO call site, so M8-8 added the command (SPEC S11 "Commands"): asks `notifyShouldScrollToTop()` (a veto returns false and moves nothing), animates to `−adjustedContentInset.top` (x kept), `didScrollToTop` follows `didEndScrollingAnimation` (or fires at once when nothing moves). M8-7's status-bar hook can call it; `scrollsToTop` stays M8-7's.
2. Phase queue only while an observer exists (`hasPhaseObservers`): zero cost otherwise. The hold is a counter, so nested sites compose; `holdingPhase` inside a batch leaves the flush to the batch's `deliverPending`.
3. Delegate dispatch is one list filtered by kind (13 boxes at most per scroll view in practice); a typed `Handler` enum instead of `Any` casts, so there is no per-frame cast on `didScroll`.
4. Velocity of `ZTronScrollPhaseChangeContext` stays the clock motion's (pt/s, nil when no motion runs): idle→tracking and tracking→interacting are nil, interacting→decelerating carries the release velocity. The finger's tracker velocity is not exposed (it lives in `PanSession`, which is not mine); native documents the same "nil when unknown".
5. R2 measured on 27.0 (`ObservationUITests.testNativeScrollViewPhasesMatchOurs`, native `ScrollView` next to ours, same synthesized press-and-drag): after the drag begins both report `interacting→decelerating→idle`; at touch-down native reports `idle>interacting` where ours reports `idle>tracking` then `tracking>interacting` (the instant `.tracking` is coalesced natively for a synthesized drag). Kept ours (D7: `.tracking` at touch-down without an arbiter). The test normalizes that prefix.
6. The 18+ twin bridge `ZTronScrollPhaseChangeContext.init(_ native:)` is `@MainActor` (the geometry init is) and the twin's native closure uses it directly.
