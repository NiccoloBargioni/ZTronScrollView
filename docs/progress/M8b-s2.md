Decisions (M8b2-n; not added to the D-list on purpose):
1. **Placement formulas are derived, not copied**: the design writes `top0 − min(g,H)/2` (y up). In viewport y-down terms the gap a pull opens is `[base, base + pull]` with `base = aci − own hold (+ header)`: `.system` is centred in it (`pull/2`), `.default` is glued to the content edge (`pull − L/2`, clipped to the gap), `overlay` slides in from outside the base (`−L/2 + min(pull, L)`, `+L` when refreshing, clipped at the base only). Pure and unit-tested; the look is a placeholder until R1.
2. **Host split**: the container's body gets one overlay line; everything else is in `RefreshOverlay` (cold, owns the env reads so a changing `RefreshAction` never re-evaluates the container or the content). `RefreshHolder` is an `ObservableObject` that never publishes (keeps the coordinator alive, nothing observes it). Actions are trampolines through `holder.latest`, so a parent re-evaluation with a new closure never rebuilds an engine; engines are rebuilt only when the signature (style, overlay, configuration, custom) changes.
3. **Declarations are stored unresolved** (`RefresherDecl.edges?`) because only the container knows the axes: `edges ?? configuration.allowedEdges ?? start edge`, narrowed to the scrolled axes (a bottom refresher on a horizontal-only view is ignored). `.refreshable` takes the start edge of the primary axis.
4. **The indicator leaf is alive only while its edge pulls or refreshes** (otherwise no `ChromeLeaf` exists: scrolling normally costs the refresh host nothing); the cold host re-renders on the coordinator's `objectWillChange`, i.e. per frame during a pull, never otherwise.
5. `onZTronScrollReachEdge` exists as a twin only (it reaches the scroll views below through the environment; works from outside a `ZTronScrollView`); the watchers live in the holder and are reconciled in place (same edge at the same index keeps its arming).
6. A custom view's binding: `.mode = .refreshing / .notRefreshing` map to `begin(runAction: false)` / `end` (as `beginRefreshing()`), other writes are ignored. The accessibility action runs the action (`begin(runAction: true)`), but not while another edge refreshes.
7. **Bug found by `RefreshUITests` and fixed in M8b-1's coordinator**: a pull whose action returned while the finger was still down (slow drag, ≥ 0.6 s after the crossing) fired a SECOND action at the lift — the lift resets `firedThisPull`, and a flush inside `endDrag` (the state still reports tracking) sampled the same pull again. `RefreshCoordinator.liftedThisTouch` masks the tracking flag from the lift to `sequenceEnded` / the first untracked sample. `RefreshLiftTests` (2 edges × 2 OS paths + next-pull test). The M8b-1 engine tests had not covered the real pan ordering.
8. Unprefixed members bind only on the `ZTronScrollView` itself: `.refresher {…}` must come BEFORE `.frame(…)` etc.; after it use `.ztronRefresher {…}`. Documented in the member's doc comment and the parity row.
9. XCUITest cannot invoke custom accessibility actions: the action is unit-tested (`RefreshAccessibility.perform` in the hosted view), the UI test checks the element (label, value, existence per edge). `allowsHitTesting(false)` on the overlay does not remove the elements from the accessibility tree.
10. `\.refresh` is read, never written: a native `List` in the content does not inherit our refresher (R9, by construction; not run against a hosted native `List`).
