Decisions (D51 for the ones that refine the SPEC; M8b3-n otherwise):
1. **D51 — a resize keeps the header's place** (S7 "keeps its collapse progress" + "centre preserved"): at or above rest `o′` is kept (a refresh hold too), inside the band the progress (`o′ = p · band_new`), and while collapsed the visible centre below the minimum-height header is preserved and the header stays collapsed. It is part of the M5 intent (`ResizeIntent.header`, `Snapshot.header` interpolated with the drawn size), so the transform effect realises it per frame and the sticky intent restores it exactly; a `size` / `.fit` change outside a resize uses the same rule (`keepProgress`). A plain centre rule cannot keep the progress: inside the band the content's top is glued to the header, so the centre moves with every collapse point.
2. **D51 — the M5 header term is `h − R`** (negative while collapsed): the resting height is part of `adjustedContentInset.top` since this session, so the old `ScrollMetrics.headerObscured` ("header beyond the insets") is not used by the header (left in place for M9; M9's pinned headers should read `HeaderMath.obscuredDelta` at their own read time). `ResizeMath` accepts negative terms (floored at `−insets.top`); every existing call passes 0.
3. `top0` = the safe-area top the content adjusts for (`aci.top − contentInset.top − hold − R`): under `.never` the header starts at the viewport's top, like the content would.
4. `.stretch` + refresher: the top indicator's base is `top0 + R` and the overlay placement is forced (S10); `.preserve` keeps the plain base (the gap opens below the resting header). With `holdOffset == indicatorHeight` every style ends centred over the band at rest.
5. Horizontal view: `HeaderContentReserve` subtracts `R` only (not the other vertical insets) from the content's height proposal, so a header-less view is unchanged; the D15 rule (zoomed content taller than the unobscured height drives the header) is in `headerOffset`.
6. `ZTronHeaderGeometryReader` always delivers a value (`ZTronHeaderGeometry.unresolved`, all zeros, until the header resolves): a reader whose content is empty at its first render never updates, because SwiftUI does not instantiate the `.background(ReaderProbe)` of an empty view (pre-existing in `ZTronScrollReader`, Open 3).
7. The `.immediately` snap is composed in offset space at the pipeline's compose hook (`endDrag`, after `decideTarget`, before `willEndDragging`), not wrapped into `effectiveTargetBehavior`: that keeps `effectiveTargetBehavior?.base as? ViewAligned…` and the natural edge bounce (a retarget happens only when the landing moves).
8. The D11 gate is a separate leaf on `.phase`; the frame leaf wakes on `.target` + `.metrics` only and reads the phase untracked for the pixel snap: `header.frame == 1` per transaction holds.
9. The host does not depend on the width, so `header.builder` is 0 at a rotation (the design allowed 1 under `.aspectRatio`); it is 1 per parent rebuild (a new closure is always applied, R7) and ≤ 2 at install on 17+ (the container's own second install pass).
10. `scrollTo` solves `o = place(aci.top + δ(o + A))` (rest, collapsed, else bisection inside the band) with `place` clamped by the REAL bounds (`TargetScrollMath.axisOffset(…bounds:)`): a probe geometry's stricter top bound broke the solve (−35 pt on a centre anchor, caught by the test).
11. `.afterFinishAccelerating` also runs after a release that does not decelerate (the reference's `didEndDragging(willDecelerate: false)`), and after a deceleration once the flush is over (never inside it).
12. **Readers during a resize** read the TARGET offset (`geometry.header` while `metrics.resize.isOpen`): the presentation is the drawn offset of the interpolated geometry while the metrics are already the new ones, so a `.stretch` banner rotating back to portrait reported a 196 pt pull to its readers (DEBUG rotation probe in a scratch worktree, `smax=195.8` → 0 after the fix; `HeaderResizeTests.whileAResizeIsOpenReadersSeeWhereItLands`). The frame leaf already reads the target.
13. Units: `.fit` reports leave layout through `DispatchQueue.main.async`; a synchronous Swift Testing test is itself a main-queue job, so its `pump` never delivers them: `HeaderFitTests` is `async` (`Task.sleep`), as USER-s6 Open 2. Swift Testing evaluated `#expect(x == 62 + 240)` with an Int literal sum and failed for x == 302.0: expectations use constants.
Open:
1. **R5 under a rotation** (the probe could not settle it: a DEBUG seam probe — header bottom vs content top at the end of every run-loop turn while the resize is open — saw only 2–3 turns per simulator rotation, all at 0 pt, so the in-between frames are not observable this way; not ported). With `.aspectRatio` / `.fit`: the new resting height is committed with the resize, unanimated, so the frame leaf jumps to the final height at the start of the rotation while the content's `GeometryEffect` interpolates: the header overlaps the content's top (portrait → landscape) or a gap shows (back) for the length of the system animation. `.fixed` headers and collapsed headers do not move (their live height does not change). Not seen by eye here (no screenshots); the end state is tested (progress kept, `R = W / r`). Options: during an open resize let the leaf read the drawn geometry (presentation + `probe.pending.size`, one frame behind), or publish the header part of the commit in the system transaction so SwiftUI interpolates the frame with the same curve (needs a device check that the geometry callback runs inside the rotation transaction).
