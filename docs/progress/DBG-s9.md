# DBG-s9 handoff · 2026-10-25 · Opus 5.5 (Debugger) — "Observation tracking feedback loop detected" in the full 27.0 unit run (Open item 7)
Status: done — root cause measured, harness fix, guard; unit 676/676 with 0 warnings on 27.0 (two runs) and 17.5 (HEAD 80e2e08: 203 warnings in 673 tests on 27.0, all tests green). No library change.
Changed:
- `Tests/ZTronScrollViewTests/Support/Unhost.swift` — `ScrollViewWindows` (iOS 26+ only, `isNeeded`): a test window that holds a `UIScrollView` and all its scroll views stay allocated until the process exits. It is *retired* (hidden, root controller dropped, so its SwiftUI content is freed and stops rendering) by `unhost` or by the first `host()` of a later test (`retireFinished`, keyed by `Test.current?.id`; every test that hosts a native scroll view is synchronous, so it has finished by then). `unhost` of any other window is unchanged (hidden, root controller dropped).
- `Tests/ZTronScrollViewTests/ReaderTests.swift` — `host()` retires finished tests' windows first and keeps its window if it holds a scroll view after its first pump (2 lines). Every hosted SwiftUI window of the suite goes through `host()` (the raw windows of `DelegateOrderTests` / `UIKitObserverShellTests` hold no scroll view).
- `Tests/ZTronScrollViewTests/HostWindowTests.swift` (new, 3 tests, iOS 26+): the keep rule, retirement by another test's `host()`, and 25 native-`ScrollView` windows released one after the other that never share an address, then 3 plain windows. Without the keeper this suite alone fails and prints 8 warnings.
- `scripts/run-filtered.sh` — counts UIKit's sentence (`Observation tracking feedback loop detected! Make a symbolic breakpoint`, so source text echoed by a compiler diagnostic does not count) in the full log; any occurrence prints `error: N UIKit 'Observation tracking feedback loop detected' warnings …` with the top objects and makes the run exit 1 (D52).

Decisions / findings (measured on a private iPhone 18 Pro 27.0 clone unless noted):
1. The warnings: all `[updateProperties]` invalidations of 200×200 `host()` windows at one or two recycled addresses, each a different window instance. Logging the window sequence in `host()`: none up to window #52 of the run, then nearly every new window warned exactly once (183 of ~278). Only 330 `host()` windows in the run, at most 11 alive at once, 1 at the end (no leak), none in a `UIWindowScene` (the test process has no scene).
2. UIKit's detector (UIKitCore of the 27.0 runtime, extracted from the simulator's dyld shared cache with Xcode's `dsc_extractor.bundle`, read with `otool`): per object and update kind it counts invalidations in a `[ObjectUpdate: Int]`, warns above `UIObservationTrackingFeedbackLoopThreshold` (default 40: `mov w9, #0x28` in `__UIObservationTrackingFeedbackLoopThreshold`), and clears the counts from `_UIObservationTrackingInstallCATransactionCommitHandler`, which is `[UIApp _performBlockAfterCATransactionCommits:]`.
3. `UIApp` is nil in the package test process (`unsafeBitCast(UIApplication.shared, to: Int.self) == 0`; `xctest` never runs `UIApplicationMain`): the reset is sent to nil, the counts never clear, and a window allocated at a freed window's address inherits its count.
4. Which objects are counted: a native SwiftUI `ScrollView` (`SwiftUI.HostingScrollView`) registers with UIKit's scroll-edge `ScrollPocketCollectorModel`, which invalidates its window's `updateProperties` twice (two key paths) and its own once. With the threshold set to 1 on the clone, `Color.clear` and `ZTronScrollView` windows recorded nothing. So the library is not involved: no body/update writes a value it reads, SPEC S4 holds.
5. Minimal repro (one test, alone, 7 s): 21 native-`ScrollView` windows released one after another at one address → from the 22nd window on every window there warns, `Color.clear` ones included. Not a cause: window count, coexisting windows, re-keying, teardown alone (6 probes of 30 windows each, 0 warnings).
6. Why it looked like "full run only, since M6 s1, never on 17.5": M6 s1 added the first suites with more than ~20 native `ScrollView` windows (NativeBridge, ScrollConfigTwin, later IndicatorModifier, ViewAligned, DefaultScrollAnchor…); a single suite stays below 21 at one address; UIKit's observation tracking does not exist before iOS 26. Suites interleave on the main actor, so the warnings landed in ~60 unrelated tests.
7. Fix choice: avoid address reuse for the counted objects (≈100 kept windows per full run plus their scroll views, retired as soon as their test is over). A first version kept the whole hierarchy live until the end of the run; it was dropped because live content of finished tests can add renders to the global `ZTronRenderCounters` of later tests (the 17.5 run with it had `ChromeLeafTests.aScriptedScrollAndZoomRun…` at `chromeLeaf.body` 60 vs 20, the documented load flake, so not proven to be the cause, but the risk is removed). Keeping is off below iOS 26 (no UIKit observation tracking there), so 17.5 and 18.x run the harness exactly as at HEAD. Not taken: a host-app unit-test target (gives the process a `UIApplication`, so counts clear per commit as in apps; it changes the test infrastructure and every session's commands, so the user decides); a hand-made `UIApplication` (unsupported); raising the threshold through user defaults (hides real loops). With the keeper the detector stays on and is stricter than in an app: an object invalidated more than 40 times in its whole life still warns.
8. D52: the warning count is asserted 0 by the script on every `scripts/test.sh` run (exit 1 plus an `error:` line, which the test-runner reports).
