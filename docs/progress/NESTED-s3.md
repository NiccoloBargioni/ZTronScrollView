Decisions:
- The registrar holds the participant weakly and the registration with the arbiter exists while the view is *placed* (`register(frame:)` called, not yet `unregister()`ed) **and** a participant is set: so the modifier and the participant can arrive in either order, clearing the participant unregisters, a replacement object re-registers with the last frame, and a frame change while no participant is set is remembered. `ArbitrationParticipant` is always both, so its behaviour is the old one (same log: register, update on change only, unregister once).
- `isRegistered` = token held **and** participant alive (a dead weak participant is not registered from the caller's side; the arbiter already treats it as unknown).
- Arbiter swap: `ZTronScrollArbitrationRegistration.setArbiter` unregisters from the old instance at once and creates a fresh registrar; `ParticipantFrameRegistration` keys its reader by `registrar.serial`, so the new reader appears afresh and registers with a frame in the *new* space (equal frames in two spaces would not fire `onChange`, and `onAppear` does not re-fire for the same reader). Serial, not `ObjectIdentifier`, so a recycled address cannot alias.
- The same keying applies to the library's own modifier, which therefore re-registers after an arbiter swap (before, the new participant stayed unregistered until the view reappeared; only reachable by changing the environment arbiter). Closures capture the registrar of the body evaluation, so a removed reader's `onDisappear` unregisters the *old* registrar, never the new one.
- `NestedScrollArbiter.beginSequence()`: `if beganLazily { endSequence() }` first. A sequence the outer began (touch-down) is not superseded (a second `beginSequence()` stays a no-op); one begun by an ask is. Mutation-checked: without the line `lazilyBegunSequenceIsSupersededByARealTouchDown` fails on both paths (stale `.participant` for the next swipe).
- `registrationSequenceEnded()` is kept for the D2 contingency only; `PanCoordinator` still calls `participantSequenceEnded()` for its own participant.
Deviations from the brief: none in the public API. The `.id(registrar.serial)` keying and the `isRegistered` rule above are additions the brief did not spell out.
Open:
- The registration does not honour `ztronNestedScrollPolicy(.independent)` (the policy belongs to `ZTronScrollView`; a foreign participant answers `canFollow` itself). Say so in A/D2 docs if it matters.
- A registration object that is deallocated without the modifier's view disappearing leaves its token in the arbiter (the arbiter treats a dead participant as unknown, but `NestedScrollArbiter.hasParticipants` stays true until `unregister`); the view's `onDisappear` normally cleans it up.
- `registrationSequenceEnded()` has no production caller (D2 decides).
For A: `PassiveRegionParticipant` registers through a `ZTronScrollArbitrationRegistration` (its `registrar` is internal, so A can add the region `kind` tag on `NestedScrollArbiter.register` and drive `ParticipantFrameRegistration(registrar:)` itself, or use the public modifier). A region never calls `participantSequenceEnded()`, which is what the supersede in `beginSequence()` covers. For D2: `ZTronScrollArbitrationRegistration` is the whole public surface (participant, modifier, `owner`); `import ScrollArbitration` stays the caller's; the `registrationSequenceEnded()` contingency needs a public forward on the registration (not added).
