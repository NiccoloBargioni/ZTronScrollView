# SHEET-s2 handoff · 2026-10-21 · Sonnet 5.5 (side session, builder)
Status: done — `View.ztronScrollYieldsToSheet(_ yields: Bool = true)` is built and verified on 27.0 + 17.5 (preferred, `--forced`, 17.5 `--forced --uikit`); parity row set; not run on a real iOS 15/16 runtime (they do not run on this Mac) nor on 18.x / 26.x.
Headline: with the flag on, a drag that starts on the view reaches the sheet. Medium, `-ZTronSheetYield api`, upward drag 250 pt: sheet top 415 → 62 (27.0) / 399 → 69 (17.5), content offset stays 0, zero pan events; at large the flag is false again and the same drag scrolls 0 → 240 with the sheet fixed; equals native `.resizes` (C1: top 62/69 both) and `.scrolls` (C2: offset 247/237 native vs 250/240 ours).

Decisions:
- A deceleration in flight at the flip is NOT interrupted: it settles on its own clock (idle, clock stopped, one `didEndDecelerating`) and nothing can catch it while inert (touch-down is dropped). "Ends like a cancelled touch" holds for a drag, an overscrolled drag, a catch and a pinch: pinned against the system's own cancel (same delegate log and state in the unit tests). Reason: a cancelled touch does not stop a finger-free motion; interrupting would freeze the content mid-air for no gain.
- Pinch and double tap are masked too (SPEC unchanged): P10/P11 show they do not need it for the sheet's sake, but an inert view must not zoom under a moving sheet.
- UIKit observer (15–16): recognizer untouched (passive, `c.uikit.began` > 0 while yielding, the sheet still got every drag); the gate lives in the coordinator.
- `isEnabled: false` on the iOS 18+ `name:` overloads frees the sheet exactly like `including: .subviews` (27.0 preferred + forced: sheet 415 → 62, 0 pan events).
Open:
- iOS 15/16 not run: `GestureMask` and `simultaneousGesture(_:including:)` are iOS 13 API (SDK interface), the 17.5 path runs the very call, and `CatchArming` already ships `including: .subviews` on 15–17; the user's 15/16 run of the sheet screen with `-ZTronSheetYield api` (+ `-ZTronForceUIKitObserver` is the default there) is still wanted.
- A flip while a finger is down on the content is unit-tested only (XCUITest has one finger and the sheet is dragged by it).
- Visible-centre rule (S7) applies to the sheet resize: with a scrolled content the offset moves while the sheet expands (Y6b 684 → 513, `both` > 0); same as V3/V4. Not a bug; do not assert `both == 0` when scrolled.
- Any environment change re-runs a content body that has a non-Equatable input (measured 27.0: an unrelated key, 2 → 8 bodies for 6 flips); the flag costs the same, an input-free content (the demo's `SheetRows`) runs 0 (`c.content.body=0` on every lane).
- Latent, not reproduced on the system path: `handle(.cancelled)` clears a held release without ending the drag on the state; `cancelForSheetYield` closes it, `cancelIfActive` alone does not (self-heals at the next touch).
- `.scrollDisabled` bridge: the debugger session owns it; `NativeEnabledBridge` was not touched.
