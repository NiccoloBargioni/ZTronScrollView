Decisions:
1. Write-back value (Q2): `viewID` of the smallest registered frame containing the anchor point of the unobscured viewport (half-open, nudged 0.25 pt into the view the anchor looks into), else `point`. Both `ZTronScrollPosition` and `id:` bindings dedupe by `(request, serial)`; a value that is not our own write clears `lastWritten` (found by the aligned UI test: a Reset to the same id was never rewritten) and a write clears `lastApplied`.
2. `withAnimation { position = … }`: the change reaches the container in an update whose transaction is not visible to `onChange`; `.transaction` only runs for animating descendants. `PositionTicket` (identity `GeometryEffect`, animatable ticket that changes with every new value) makes SwiftUI evaluate the transaction, `.transaction` hands the animation to the driver, which scrolls inside `withAnimation(a)`. Works on both OS paths (unit test: mid-flight offset between start and target).
3. **D32 / R4**: SwiftUI's `ScrollTargetBehaviorContext.velocity` is points per millisecond (native 0.6 vs 644 pt/s measured in ours for one swipe, on 27.0 and 17.5). First kept ours pt/s with a ×1000 bridge; the user then decided to match SwiftUI: `ZTronScrollTargetBehaviorContext.velocity` is pt/ms (`decideTarget` ÷ 1000, bridge pass-through, `rawVelocity` and the physics stay pt/s; `TargetBehaviorTests` updated).
4. **R5** on 27.0: never / byFew / automatic already matched; `.alwaysByOne` did not (ours moved one item from the drag start, SwiftUI one beyond the lift). Fixed; all four now land on SwiftUI's item. On 17.5 SwiftUI's `scrollPosition(id:)` kept reporting 0 in this screen, so only ours is asserted.
5. **Open 4**: SwiftUI's proxy scrolls the upper of two scroll views holding the id (27.0 and 17.5); ours scrolled the lower (onAppear fires in reverse tree order). Switched to frame order; verified equal.
6. 17.5 crash found on the way: a class nested in an `@available(iOS 18)` type stored a `ScrollPosition`; the runtime realizes every class at load, xctest died before running (fixed in 17fc47a: type-erased).
