Root cause for user2 (not fixed): `cidle` (= `resize.contentSizeIdle`) increments at every rotation → the reflowed content size (402×1206 ↔ 750×2250) arrives while NO resize is open (before `setViewport` or after `closeResize`), so it is handled by the idle `.sizeChanges` rule (clamp / anchor), which moves the view and the sticky intent is then realised against a wrong starting point (first rotation jump=1). In the 16:9 tree the reflow lands inside the resize window (`cidle=0`), hence the exact round trip there. Fix (next): in `setContentSize` idle path, when `resizeIntent != nil` (or a viewport change follows within the same frame) realise the sticky intent with `ResizeMath.realize` instead of the anchor rule, and capture the intent BEFORE applying an idle reflow when none exists; then re-run both screen-space tests. Also fix the test's `visibleCentre` (use the `scrollerView` frame centre directly, or subtract only the insets XCUI did not already remove).
