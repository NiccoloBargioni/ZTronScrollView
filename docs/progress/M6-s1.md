Decisions (M6s1-n; not added to the D-list on purpose):
1. SDK names win over the design's sketch: protocol requirement `properties(context:)` and flag `limitsScrolls` (kept `limitsVelocity` as the
   design's alias, same stored flag); `context.horizontalSizeClass` (dot syntax) replaces the design's `context[\.horizontalSizeClass]`.
   Requirements are `@MainActor` (the registry lives there); a conformer may implement them without isolation.
2. `ScrollTarget` has no public initializer (checked: the compiler refuses): the 17+ conversion is `init(_ native:)` plus `write(to:)` into the target SwiftUI
   hands out; there is no `var native`. `AnyZTronScrollTargetBehavior` mirrors `AnyScrollTargetBehavior` (`base`), no closure box.
3. `.paging` calls `PagingSolver` from the lift offset, the drag start and the RAW release velocity (internal `TargetReleaseInfo`), so its end positions equal
   the legacy knob's within 1e-6 (a retargeted decay lands to ~1e-13; tested over a 19-row table, both paths). `isPagingEnabled` is the `.paging` behavior inside the pipeline
   (`ReleaseSettings.isPagingEnabled` still carries the knob, the state's `effectiveTargetBehavior` mirrors it); an explicit behavior wins.
4. `limitsVelocity` caps the velocity (container length ÷ the rest distance of a 1 pt/s fling) for the context and the NATURAL landing point only. The `ReleaseSolver`
   and `willEndDragging` keep the raw accelerated velocity, so `.paging` moves exactly as before and a limited fling still lands within one container.
5. A target is handed to the solver iff the behavior is a snapping built-in (`.paging`) or `proposed != natural`: a no-op custom behavior keeps the
   natural decay (edge bounce included); a page flick back at the first page does not bounce (legacy).
6. Registry: owned by the state (`state.targets`, `usesGeometryChange` fixed with it, R6). One report per live reporter, the id shows the newest active
   one and falls back to an older one when it goes (SwiftUI can build a copy of the content, register it and discard it); `onDisappear` retires the
   frame and `onAppear` restores it (a `NavigationStack` push disappears views that stay alive); the preference default is `CGRect.null`.
7. `scrollTo(id:)`: stops a motion first; `ambient` → `scroll(to:)` (transaction path), `nil` → `setContentOffset(animated: false)`, `.uikit` → clock,
   `.swiftUI(a)` → `withAnimation(a) { scroll(to:) }`; unknown id → `false` (the proxy then asks the SwiftUI proxy, silent like native); a known id before the
   first layout is handled and moves nothing (the pending retry is session 3's PositionDriver).
8. Proxy scope: members in appear order, nested readers weakly (own members first, then nested scopes); the inner scope is not reached from sibling scopes.
9. The captured environment (for `context.<key>`) lives in a box owned by the capture leaf; the state references it weakly. A strong copy in the state is a
   retain cycle (the container's environment carries the state and the scope; a negative control proves it, and an `EnvironmentValues` copy with a key
   set to nil still retains the old value).
Open:
1. **DECISION NEEDED before session 2 (target space).** Measured on 17.5 and 27.0 (`NativeBridgeTests`, notes folder `M6-s1-findings.md`): SwiftUI's
   `ScrollTarget.rect` is in content coordinates (`offset + adjustedContentInset.top`) and its container is the UNOBSCURED size, native `.paging` pages are that
   size. Ours (design M6 §4, kept): `rect.origin == contentOffset`, container == full viewport, paging page == viewport (UIKit's `isPagingEnabled`). They
   coincide with zero insets; with insets a behavior ported from SwiftUI sees shifted values. Adopting the native convention is one place (`decideTarget`:
   origin += insets.start, container = unobscured, landing −= insets.start; `.paging` can convert and keep its legacy numbers). Recommended: adopt it for the presented
   values before ViewAligned (session 2) builds on them; keep the legacy page length.
