Decisions (M8b1-n; not added to the D-list on purpose):
1. The hold is `ScrollMetrics.refreshHold`, summed into `adjustedContentInset` (bounds, indicators, M5 centre, resize commit all follow it). Two ways to change it: `followsOffset: false` = bounds only, the offset is untouched; `true` = the M5 inset-only rule (start edge follows its edge) in the caller's transaction.
2. Open at the lift = bounds only, BEFORE the release pipeline reads them: `PanCoordinator.apply(.release)` calls `refresh.lift` then re-reads the environment, so `ReleaseSolver` springs an over-pull to `−(aci.top + H)` with no offset write at the lift (no remap of the rubber band, no jump). A lift that leaves the offset inside the hold band (0 < pull < H, e.g. the finger came back after a `.whilePulling` trigger) cannot decay to the hold bound by itself: `finishRelease()` scrolls there (design said "decays to it").
3. Sample call = `state.onFlush`, run at the end of `deliverPending()` (after the delegate's `didScroll`, ≤ 1 per frame while a finger / motion writes; also at the end of any non-deferred batch, so a motion that settles outside `step` still reaches a finishing edge). Ticks are folded into samples. A finishing edge also gets ONE one-shot timer for its deadline (the frame clock is idle at rest and a refresh must not keep it running); `schedule` is injectable, the tests fire it by hand.
4. Clear = `finish` when `time ≥ since + minimumVisibleTime`, no finger down AND no motion without a finger (`isSettled`). With a finger down it waits for the lift and then closes the hold with bounds only (the release springs the content to rest); with no finger the M5 rule returns the content to rest inside `resetAnimation` (`.swiftUI(a)`: `withAnimation`; `.uikit`: bounds then `setContentOffset(animated:)`; `nil`: unanimated). `since` = the moment the hold opened (lift or `beginRefreshing`).
5. An action that returns while the finger is still down (`.triggered`) never holds: the mode returns to `.notRefreshing` and the same pull cannot fire again (`firedThisPull` survives until the sequence ends).
6. `beginRefreshing(edge:)` with a finger down is deferred to the end of the touch; with no refresher on that edge it is a no-op (a state used before the first appear also ignores it). `endRefreshing` cancels the running action Task (a generation counter drops its late completion) and honours the minimum visible time.
7. `onZTronScrollReachEdge` distance is measured against the bounds with the hold included (`d_top = o − bounds.min`, `d_bottom = bounds.max − o`); silent until the first layout; at the first valid layout a watcher already at its edge fires (short content / list at the top): "arrival" includes appearing there.
8. Bounce force is axis-wide through `RefreshCoordinator.bouncesVertical/Horizontal` read by `peekEnvironment()` (Q1).
9. `DoneToken` + `RefresherSpec.awaiting` ship now so M8b-2's public completion overloads only wrap them; "`done` idempotent from any thread" is proven with 16 racing threads (a second continuation resume would trap).
10. Tests that need the action `Task` to run are `async` and suspend with `Task.yield()`: a nested run loop cannot run it, because the test itself is a job on the main queue (`pump` is fine for SwiftUI/Observation, not for Swift tasks).
