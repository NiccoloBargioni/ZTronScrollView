# SHEET-s1 handoff · 2026-10-21 · Sonnet 5.5 (side session, measurement spike, no library change)
Status: done — the question is answered with measurements; nothing is designed or implemented. Report: `docs/design/SHEET-spike.md` (results table ours vs native per case per OS, mechanism, what is / is not fixable in pure SwiftUI, recommendation). Not run: real iOS 15/16 (runtimes do not run on this Mac); 18.x / 26.x (only 27.0 and 17.5, as asked).
Headline: **a drag that starts on a ZTronScrollView never reaches the sheet** (sheet top constant in all 14 cases × 5 paths; content always wins; `both` = 0, no double movement). It is not ZTron-specific: any recognized SwiftUI `DragGesture` / `SpatialEventGesture` under the finger freezes the sheet, a pane with no gesture dismisses it (controls P1–P6, P9). On 27.0 the sheet's `_UIFlexInteractionPanGestureRecognizer` still begins and delivers the whole drag but declines to move the sheet. Masking the gestures with `including: .subviews` frees the sheet (P7, P8, P12, both OSes, also `--forced --uikit`), so a per-detent `ztronScrollYieldsToSheet(_:)` is feasible in pure SwiftUI (~1–1.5 %); the live top-edge hand-off is not (the sheet decides at touch-down; native itself has no mid-gesture hand-off, D2).
